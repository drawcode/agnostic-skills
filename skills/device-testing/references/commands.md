# `device` commands

Generated by `device help --markdown`; regenerate after adding a command.

`device [--device ALIAS|SERIAL|UDID] <command> [args]`. Same commands on every platform; the attached device decides the backend.

Exit codes: 0 ok, 1 failed, 2 a wait or check came back negative, 3 not supported on this platform.

| Command | Arguments | What it does |
|---|---|---|
| `devices` |  | attached devices: platform, serial, model, alias |
| `alert` | `accept\|dismiss\|text\|watch S [accept\|dismiss]` | a system alert, through WebDriverAgent (iOS only, opt-in); watch answers every alert that shows within S seconds and prints its text |
| `apk-symbol` | `<apk> <symbol>` | alias of build-symbol |
| `appearance` | `[dark\|light]` | read or set the system dark/light style |
| `awake` | `on\|off` | keep the device awake for a pass (preflight turns it on); off releases what iOS holds |
| `bg` |  | send it to the background, then prove it lost the focus |
| `build-symbol` | `<build> <symbol>` | is the change compiled into this APK/IPA |
| `burst` | `<prefix> <n> <gap> [--swipe X1,Y1,X2,Y2 [--swipes K] [--alternate] [--settle S]] [--norm]` | n screenshots gap seconds apart plus one contact sheet; with --swipe, each round is K swipes gap apart, a settle wait (default 3 s), then the still; --alternate reverses the swipe every second round |
| `check` |  | resolved config, device, app, nav profile |
| `clear-data` | `[--grant PERMISSION]...` | wipe the app's data (first-run state, forces a re-login), then grant runtime permissions; Android |
| `clipboard` | `set <text> \| get` | the device clipboard (iOS: CoreDevice pasteboard, exact UTF-8; Android has no host route, exit 3). Pasting into a field is a separate step |
| `count` | `<regex>` | log matches right now (the baseline before an action) |
| `crashes` | `[--since TIME] [--pull DIR] [--fail]` | the app's crash reports (iOS .ips, Android crash/ANR/native crash records), newest last; none is a clean result; --fail exits 2 when any is found. TIME: 30m, 2h, 1d, a date or HH:MM |
| `deselect` |  | clear focus, which closes the keyboard |
| `focus` |  | what is in front; non-zero if it is not the app |
| `forward` |  | USB port forward to the app's input server, one Mac port per device |
| `info` |  | input server: screen size, keyboard visible/area, focused object |
| `install` | `<build> [--symbol SYM]` | refuse unless SYM is in the build, then verify |
| `key` | `<KEYCODE> [--wait RE] [--timeout S]` | Android keycodes; iOS maps HOME, POWER, VOLUME_*, DEL, ENTER |
| `keyboard` |  | system style, keyboard state, input mode (+ native detail) |
| `launch` | `[--timeout S] [--input-server] [--url URL] [--accept-alerts [S]]` | launch and wait until the app is in front; --url opens a deep link in it; --accept-alerts watches S seconds (default 20) after launch and accepts each system alert, through WebDriverAgent (iOS only, opt-in) |
| `location` | `set <lat> <lng> \| route <gpx\|csv> [--speed M/S] \| clear` | simulate the GPS position for every app; always `clear` when done. `route` walks the file at --speed (default 1.4) and stays at its last point |
| `log` | `<regex> [n]` | the last n matching lines (default 40) |
| `log-clear` |  | clear the log buffer, so a later count or wait starts from zero |
| `media` | `build\|install\|push <file...> [--album NAME]\|hide-others [--album NAME]\|unhide\|picker` | the Photos library on an iOS device, through the media helper app (WDA team signing; WDA answers its prompt). hide-others hides everything outside the album for a clean capture and records it; unhide restores exactly those. Nothing is ever deleted |
| `native` | `start\|stop\|status\|build\|install\|tap\|hold\|swipe\|press\|keys\|source` | opt-in WebDriverAgent (iOS only), for UI the platform draws itself: the soft keyboard's keys and system alerts. Never the default input. `tap <x> <y>`, `hold <x> <y> [ms]`, `swipe <x1> <y1> <x2> <y2> [ms] [--hold ms]` (hold first: long-press-and-slide) ([--wait RE] [--timeout S] [--norm]); `press <label> [--hold ms]`; `keys <label>... [--gap ms]` (one action, no per-key lookup; still ~5 s a key over a game); `source [--grep RE]` |
| `nav` | `<id> [--timeout S] [--dry-run]` | a named step from the nav profile, waiting on its evidence |
| `nav-list` |  | every step the profile defines |
| `network` | `<profile> [--relaunch [--input-server]] \| list \| clear` | simulate a network condition (a bad link, 100% loss); always `clear` when done. iOS applies it only to an app started under it, so --relaunch restarts the app (a running or devicectl-launched app is unaffected); `clear` then relaunches it normally |
| `ocr` | `[image] [--region X1,Y1,X2,Y2] [--match RE]` | read the text on a screenshot (a fresh one when no image), one line each: cx cy text. macOS Vision; --region crops the listing to a pixel box |
| `pause` | `<seconds>` | alias of sleep |
| `perf` | `sample <seconds> [name] [--dir DIR]` | sample the running app: frames per second, CPU, memory. Writes <name>.csv and prints a summary line. Frame rate is the compositor's on iOS and the app surface's on Android; each can read n/a |
| `preflight` | `[--keep-logs]` | clean room: unlocked, awake, logs ready, app stopped, logs cleared |
| `prefs` | `[key]` | the app's preferences, or the lines around KEY |
| `quiet` | `on\|off\|status [--confirmed]` | silence notifications before recording or screenshots: Android sets do not disturb, heads-up off, status-bar icons hidden (off restores them); iOS has no host-side switch, so it prints the steps and --confirmed records that they were done (stale after 12 h) |
| `record` | `start\|stop [name] [--segments]` | screen video into the scratch dir; --segments (Android) chains 170 s clips so a take can pass 3 minutes, and stop joins them with ffmpeg |
| `resume-check` | `[--hold S] [--settle S] [path]` | background, return, settled screenshot |
| `rotate` | `left\|right` | turn the device 90 degrees as if by hand (counterclockwise or clockwise); prints the orientation it reports |
| `run` | `<plan> [--keep-going] [--verbose]` | run a plan file: one command per line (# comments), stop on the first failure unless --keep-going, always run the lines after `finally:`. Any device command is a plan line (tap, swipe, key, native ..., nav, wait, sleep, shot, record, ...). Output is compact: one `ok\|FAIL <ms> <cmd>` line per step, the last ~15 matching lines of a failed step, a `files` line naming every screenshot/log/video made, and a full log path; --verbose streams each step live. Exit 1 if any step failed |
| `sheet` | `<out.png> <image>... [--cols N] [--width PX]` | contact sheet of screenshots |
| `shot` | `[path] [--max-height N]` | screenshot; prints the small viewing copy (_s) first, then the full-size path. N defaults to SHOT_MAX_HEIGHT (1000); 0 = full size only. Read the _s copy, it costs a fraction of the tokens |
| `sleep` | `<seconds>` | wait, so a plan can let an animation settle |
| `stop` |  | stop the app, then PROVE the process is gone |
| `swipe` | `<x1> <y1> <x2> <y2> [ms] [--wait RE] [--timeout S] [--norm]` | swipe; pixels of the screen, or 0-1 with --norm |
| `tap` | `<x> <y> [--wait RE] [--timeout S] [--norm]` | tap; pixels of the screen, or 0-1 with --norm |
| `text` | `<value>` | set the focused input field directly |
| `type` | `<text>` | type through the native keyboard |
| `version` |  | installed version of the app |
| `wait` | `<regex> [baseline] [timeout]` | poll until the count passes baseline (0, 15s) |
